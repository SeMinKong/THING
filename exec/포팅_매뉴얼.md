# 포팅 매뉴얼

> 프로젝트: ROS 2 기반 텐던 구동 손동작 모방 로봇
>
> 기준: `main` 브랜치, `docs/requirements/요구사항 명세서 V7.1.md`
>
> 소스 코드는 GitLab에서 받으며 `exec/`에 중복 저장하지 않는다.

## 0. 시스템 구성

```text
RGB Camera
   ↓
Jetson Orin Nano
Vision · MediaPipe · MJPEG · Web Bridge · Logger/Uploader
   ↓ ROS 2 DDS
Raspberry Pi 5
Command Manager · Safety Manager · Motor Driver
   ↓ U2D2 / Serial
7 × DYNAMIXEL XL330-M288-T
   ↓
텐던 구동 로봇 손

Laptop Browser ── WebSocket/MJPEG ── Jetson
Jetson Uploader ── HTTPS ── AWS EC2 데이터 포털
```

### 운용 원칙

- 논리축은 엄지 3축과 일반 손가락 4축으로 총 7축이다.
- 카메라와 MJPEG는 항상 실행하며 웹의 기록 버튼은 카메라를 켜는 버튼이 아니다.
- 기록은 `MIMIC` 모드에서만 가능하고 영상은 저장하지 않는다.
- rosbag2에는 landmark, 7축 명령, 모터 상태가 포함된다.
- 기록 종료 후 성공·실패 판정을 완료해야 다음 기록을 시작할 수 있다.
- 웹이 종료되어도 Raspberry Pi의 Watchdog, 범위 제한, E-Stop은 독립 동작한다.

## 1. GitLab 클론 이후 빌드 및 배포

### 1.1 실행 환경

| 장치 | 환경 | 주요 구성 |
|---|---|---|
| Raspberry Pi 5 | Ubuntu 24.04 호스트, Ubuntu 22.04 ROS 컨테이너 | ROS 2 Humble, CycloneDDS, DYNAMIXEL SDK |
| Jetson Orin Nano | JetPack 6.2, Ubuntu 22.04, Docker | ROS 2 Humble, OpenCV, MediaPipe 0.10.9 |
| Laptop | Node.js 20.19 이상 | React 19, Vite 8, Chrome/Edge |
| AWS EC2 | Python 3.12, Node.js 20 | Django 6, DRF, Gunicorn, Nginx, SQLite |

- JVM/WAS는 사용하지 않는다. 백엔드 WAS 역할은 Gunicorn, 웹서버 역할은 Nginx가 담당한다.
- IDE는 필수 런타임이 아니며 VS Code 등 원하는 도구를 사용할 수 있다.

### 1.2 저장소 받기

STL·BLEND·영상 파일은 Git LFS로 관리한다.

```bash
sudo apt install -y git git-lfs
git lfs install
git clone --branch main \
  https://lab.ssafy.com/s15-webmobile3-sub1/S15P11C103.git
cd S15P11C103
git lfs pull
git rev-parse HEAD    # 배포 commit 기록
```

### 1.3 ROS 2 공통 빌드

```bash
source /opt/ros/humble/setup.bash
cd thing_ws
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install
source install/setup.bash
colcon test
colcon test-result --verbose
```

두 ROS 장치는 동일한 값을 사용한다.

```bash
export ROS_DOMAIN_ID=103
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export CYCLONEDDS_URI=file:///absolute/path/to/cyclonedds.xml
```

`cyclonedds.xml`은 `thing_ws/src/thing_bringup/config/cyclonedds.template.xml`을 복사해 장치의 실제 네트워크 인터페이스를 지정한다.

### 1.4 Raspberry Pi 5

#### 하드웨어 설정

- DYNAMIXEL `XL330-M288-T` 7개, Protocol 2.0, 1 Mbps를 사용한다.
- `motors.yaml` 기준 BUS_A·BUS_B·BUS_C의 U2D2 장치 경로를 실제 `/dev/serial/by-id/...` 값으로 변경한다.
- 사용자를 `dialout` 그룹에 추가하고 컨테이너에 U2D2 장치를 전달한다.
- 모터 전원과 Raspberry Pi 전원을 분리하고 물리적 E-Stop을 먼저 연결한다.

주요 설정 파일:

- `thing_ws/src/thing_bringup/config/motors.yaml`
- `thing_ws/src/thing_bringup/config/control.yaml`

#### 실행

기존 시연 장치의 표준 기동 방식은 Raspberry Pi 호스트의 Docker Compose이다.

```bash
cd /home/rpi103/rpi-ros2-humble
docker compose up -d ros2
docker compose ps
```

노드를 직접 점검할 때만 컨테이너의 서로 다른 터미널에서 다음 launch를 각각 실행한다.

```bash
source /opt/ros/humble/setup.bash
source /thing_ws/install/setup.bash
ros2 launch thing_bringup control.launch.py

# 별도 터미널
source /opt/ros/humble/setup.bash
source /thing_ws/install/setup.bash
ros2 launch thing_bringup thing_bringup.launch.py
```

Windows 개발 PC에서 원격 실행할 경우:

```powershell
.\exec\start_rpi_demo.ps1
# 종료
.\exec\stop_rpi_demo.ps1
```

> 현재 `deploy/raspberry-pi/`에는 Dockerfile·Compose가 포함되어 있지 않다. 따라서 위 절차는 기존 시연 장치의 `/home/rpi103/rpi-ros2-humble` 환경을 전제로 한다. 신규 Raspberry Pi를 처음부터 포팅하려면 U2D2 장치와 host network가 반영된 Dockerfile·Compose를 먼저 저장소에 추가해야 한다.

### 1.5 Jetson Orin Nano

MediaPipe는 ROS의 NumPy·OpenCV ABI 충돌을 막기 위해 다음과 같이 설치한다.

```bash
python3 -m pip install --no-deps -r vision/requirements.txt
```

권장 통합 실행:

```bash
cd web/frontend
npm ci
cd ../..
bash scripts/run_jetson_vision_web.sh
```

이 스크립트는 Docker 이미지를 빌드하거나 컨테이너를 새로 생성하지 않는다. 기본적으로
`thing-jetson-full` 컨테이너와 컨테이너 내부의
`/home/c103/S15P11C103/thing_ws/install/setup.bash`가 이미 존재해야 한다.
현재 `deploy/jetson/`에는 Dockerfile·`docker run` 배포 파일이 없으므로 신규 Jetson의
완전한 재현 배포는 해당 파일을 먼저 추가해야 한다.

개별 실행:

```bash
ros2 launch thing_bringup vision.launch.py
ros2 launch thing_bringup web_bridge.launch.py
ros2 launch thing_bringup logger.launch.py
```

`logger.launch.py`가 logger와 uploader를 함께 실행하므로 uploader를 다시 실행하지 않는다.

Uploader 환경 파일 `/etc/thing-uploader.env`:

```text
THING_UPLOADER_TOKEN=<ROBOT_TOKEN>
THING_EC2_UPLOAD_URL=https://i15c103.p.ssafy.io/api/v1/uploads/sessions
THING_UPLOADER_SOCKET=/run/thing-uploader/uploader.sock
THING_UPLOADER_SOCKET_MODE=0660
THING_UPLOADER_TLS_VERIFY=true
```

비밀값 파일은 권한을 `600`으로 설정하고 Git에 커밋하지 않는다.

### 1.6 내부 관제 웹

Jetson 통합 스크립트를 사용하면 브라우저에서 `http://<Jetson-IP>:5173`으로 접속한다. Laptop에서 직접 실행하려면:


### 1.8 배포 특이사항 및 확인

- WebSocket: `ws://<Jetson>:18000/ws/robot-state`
- MJPEG: `http://<Jetson>:8080/stream.mjpg`
- EC2 HTTPS: `443`
- Jetson과 Raspberry Pi는 같은 서브넷·`ROS_DOMAIN_ID`를 사용하고 NTP/chrony로 시각을 동기화한다.
- 모터 자동 RUN 복구는 금지한다. 재시작 후 Safety 상태와 E-Stop을 다시 확인한다.
- HTTPS 페이지에서 HTTP MJPEG를 열면 브라우저가 차단할 수 있으므로 내부 관제 화면은 HTTP로 접속한다.
- Nginx의 `client_max_body_size`는 `211M`을 유지한다.

정상 확인:

```bash
ros2 node list
ros2 topic hz /thing/command
curl --max-time 3 -o /dev/null http://<Jetson-IP>:8080/stream.mjpg
curl -sS https://<DOMAIN>/health
```

권장 기동 순서:

```text
E-Stop·전원 확인
→ Raspberry Pi Safety/Control
→ Raspberry Pi Motor Driver
→ Jetson Vision/Web Bridge/Logger
→ 관제 웹
```

## 3. DB 덤프 최신본

EC2는 `/var/lib/thing-data/db.sqlite3` 단일 SQLite DB를 사용한다. 원천 데이터 4개 파일은 `/var/lib/thing-data/sessions/{robot_id}/{session_id}/`에 저장한다.
주요 데이터 모델은 세션 메타데이터를 보관하는 `Session`이며, Django 마이그레이션을 ERD와 스키마의 기준으로 사용한다.

### 덤프 생성

```bash
mkdir -p <REPO_ROOT>/exec/db
sudo systemctl stop thing-database-web
sqlite3 /var/lib/thing-data/db.sqlite3 ".dump" \
  > <REPO_ROOT>/exec/db/thing_data_$(date +%Y%m%d).sql
sudo systemctl start thing-database-web
```

### 복원

```bash
sudo systemctl stop thing-database-web
sqlite3 /var/lib/thing-data/db.sqlite3 < <REPO_ROOT>/exec/db/<dump-file>.sql
sudo chown ubuntu:ubuntu /var/lib/thing-data/db.sqlite3
sudo systemctl start thing-database-web
```

- 덤프에는 실제 토큰과 개인정보를 포함하지 않는다.
- DB 덤프가 없으면 `python manage.py migrate`로 빈 DB를 생성한다.
- 시연 데이터는 `python manage.py make_session ...`으로 생성할 수 있다.

## 4. 시연 시나리오

### 4.1 사전 준비

1. 로봇 손 주변을 비우고 물리적 E-Stop을 누른 상태에서 전원을 연결한다.
2. 카메라, U2D2 3개, 7개 모터와 내부 네트워크를 확인한다.
3. Raspberry Pi 제어 스택과 모터 드라이버를 실행한다.
4. Jetson 통합 스크립트를 실행한다.
5. 웹에 접속해 WebSocket, MJPEG, Safety, 7개 모터 상태를 확인한다.
6. 이상이 없으면 E-Stop을 해제하고 `READY` 상태를 확인한다.

### 4.2 모방 모드 및 데이터 기록

1. 메인 화면에서 **모방**을 선택한다.
2. **모방 모드와 제어권 획득**을 선택한다.
3. 카메라 화면에서 손 landmark와 7논리축 값이 표시되는지 확인한다.
4. 손 펴기, 주먹, 엄지 대립 동작을 수행해 로봇 손이 따라오는지 확인한다.
5. **기록 시작**을 누르고 파지 동작을 수행한다.
6. **기록 종료**를 누른다.
7. 결과에 따라 **성공** 또는 **실패**를 선택한다.
8. 판정 완료 후 다음 기록 버튼이 다시 활성화되는지 확인한다.

기대 결과:

- 영상은 계속 표시되지만 파일로 저장되지 않는다.
- rosbag2에 landmark, 명령, 모터 상태가 기록된다.
- 세션별 `metadata.json`, `hand_command.csv`, `motor_status.csv`, `landmark.json`이 생성된다.

### 4.3 조작 모드

1. 활성 모드에서 바로 전환하지 않고 먼저 **정지(STOP)**를 선택한다.
2. 메인 화면에서 **조작**을 선택하고 MANUAL 제어권을 획득한다.
3. 손 펴기, 주먹, 엄지–검지 집기, 원통 파지 명령을 차례로 실행한다.
4. 동작 중 새 명령이 큐에 누적되지 않는지 확인한다.

### 4.4 안전 및 업로드 확인

1. 동작 중 물리적 E-Stop을 눌러 모터 구동이 중단되는지 확인한다.
2. E-Stop 해제 후 자동으로 다시 움직이지 않는지 확인한다.
3. 기록 세션이 HTTPS로 EC2에 업로드되는지 확인한다.
4. EC2 포털에서 READY 세션과 4개 데이터 파일을 조회·다운로드한다.

### 4.5 종료

1. 웹에서 제어를 정지하고 `DISABLED/READY` 상태를 확인한다.
2. Jetson 실행 프로세스를 종료한다.
3. `exec/stop_rpi_demo.ps1` 또는 각 launch의 `Ctrl+C`로 Raspberry Pi 노드를 종료한다.
4. 모터 전원을 먼저 끄고 Jetson과 Raspberry Pi를 종료한다.
