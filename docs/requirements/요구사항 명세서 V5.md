## 1. 프로젝트 개요

### 1.1 프로젝트 배경 및 목적

본 프로젝트는 카메라로 사용자의 실제 손 자세를 인식하고, 텐던 방식으로 구동되는 3D 프린팅 로봇 손이 해당 동작을 실시간으로 따라 움직이도록 구현하는 것을 목적으로 한다.

기존의 정교한 로봇 손은 손가락 관절마다 별도의 모터와 센서를 사용하기 때문에 가격, 무게, 제작 난도가 높다. 본 프로젝트에서는 각 손가락의 여러 관절을 하나의 모터로 함께 구동하는 underactuated 구조를 적용하여 제한된 기간과 자원 안에서 사람 손의 주요 동작을 재현한다.

B2C로 손가락의 움직임 데이터를 확보한 뒤 B2B로 foundation 모델을 제공한다.

최종적으로 다음 기능을 시연하는 것을 목표로 한다.

- 실제 손의 펴기와 쥐기, 카판지 엄지 대립 및 벌림 검사 동작 모방
- 원통형 물체 파지
- ROS 2 기반 무선 제어
    - MediaPipe landmark, 7논리축 목표 명령 및 모터 상태 기록
- 웹을 통해 로봇손 조작모드와 모방모드를 시연할 수 있다.
- 추후 손 동작 테스트 해보고 추가
- 엄지와 검지를 이용한 집기
- 통신 단절 시 안전 동작

프로젝트 개발 기간은 총 3주이며, vision을 통한 손가락 동작 모방과 반복 가능한 파지 성능 확보를 우선한다.

### 1.3 제품 및 시스템 기능 요약

시스템은 크게 손동작 인식부, 명령 생성부, 로봇 손 제어부, 기구 구동부로 구성된다.

- 카메라와 Vision Node는 시스템 실행 중 항상 동작한다. 웹의 녹화 버튼은 카메라 실행 여부를 제어하지 않고 rosbag2 데이터 기록만 시작하거나 종료한다.

웹사이트는 MIMIC 모드와 MANUAL 모드 모두에서 영상, landmark, 7논리축 목표값, 모터 상태 및 안전 상태를 관제할 수 있어야 한다.

- MIMIC 모드: 사용자의 손동작을 실시간으로 모방한다.
- MANUAL 모드: 웹 버튼으로 사전 정의 자세 또는 연속 동작을 실행한다.
- 데이터 녹화는 MIMIC 모드에서만 사용할 수 있다.
- 녹화 중에는 제어 모드를 변경할 수 없다.
1. 사용자가 웹사이트에 접속한다.
2. 모방모드에서 실시간으로 MediaPipe를 이용해 인식과 동작확인이 가능하다.
    1. RGB 카메라가 사용자의 손 영상을 입력받는다.
    2. Jetson에서 MediaPipe를 이용해 손 landmark를 검출한다.
    3. landmark를 이용해 5개 손가락 굽힘값과 엄지 대립 및 벌림값을 계산한다.
        1. 계산된 7논리축 목표값을 ROS 2 토픽으로 발행한다.
3. 조작모드에서 실시간으로 로봇손의 조작이 가능하다.
    1. 사용자가 특정 명령(버튼, 키보드 등)을 내린다.
    2. 해당 명령에 맞는 7논리축 목표값을 ROS 2 토픽으로 발행한다.
4. Raspberry Pi가 명령을 수신하고 값의 범위와 유효성을 검사한다.
5. Raspberry Pi가 목표값을 보간하고 모터 속도와 위치를 제한한다.
6. 서보가 스풀과 텐던을 당겨 로봇 손가락을 움직인다.
7. 모터 상태 및 시스템 상태를 ROS 2 토픽으로 발행하고 저장한다.

### UC-06. ROS 2 시스템 실행

1. 사용자가 장치별 bringup launch를 실행한다.
2. Jetson은 카메라, MediaPipe, 손 목표 생성, MJPEG 및 Web Bridge 노드를 실행한다.
3. Raspberry Pi는 command manager, command guard, safety manager 및 DYNAMIXEL 제어 노드를 실행한다.
4. 사용자가 웹 또는 로컬 프로그램에서 제어 모드를 선택한다.
5. command manager가 현재 제어 모드와 제어권에 맞는 입력원 하나를 선택한다.
6. command guard가 선택된 명령의 timestamp, 범위, 속도 및 안전 상태를 검사한다.
7. 검증된 목표만 DYNAMIXEL 제어 노드에 전달한다.
8. 모터 상태, 제어 모드, 안전 상태 및 진단 정보를 ROS 2 토픽으로 발행한다.

제어 모드는 다음과 같이 구분한다.

- `DISABLED`: 일반 명령 비활성화
- `MIMIC`: MediaPipe 기반 실시간 손동작 모방
- `MANUAL`: 웹에서 Gesture 서비스와 Sequence 액션 실행
- `TELEOP`: 로컬 키보드 기반 개별축 조작

웹은 MIMIC과 MANUAL 모드 모두를 관제할 수 있다. 데이터 녹화는 MIMIC 모드에서만 허용하며 녹화 중에는 제어 모드를 변경할 수 없다.

## 3. 기능 요구사항

우선순위는 다음과 같이 구분한다.

- **Must:** MVP 완료를 위해 반드시 필요한 기능
- **Should:** 가능하면 구현해야 하지만 단순화할 수 있는 기능
- **Could:** 시간이 남을 경우 구현하는 기능

### 3.1 손 자세 인식

#### FR-01. 손 landmark 검출

**우선순위: Must**

시스템은 RGB 카메라 영상에서 사용자의 한쪽 손을 검출하고 MediaPipe 기반 21개 landmark 좌표를 생성해야 한다.

인수 조건:

- 한 번에 한 손을 검출할 수 있어야 한다.
- landmark를 카메라 영상 위에 표시할 수 있어야 한다.
- 손이 검출되지 않은 상태를 구분할 수 있어야 한다.
- 손 검출 여부와 정확도 정보를 제공해야 한다.

#### FR-02. 손가락 굽힘값 계산

**우선순위: Must**

시스템은 검지, 중지, 약지, 소지 및 엄지의 landmark를 사용하여 각 손가락의 굽힘 정도를 계산해야 한다.

인수 조건:

- 각 손가락의 굽힘값을 `0.0~1.0` 범위로 표현해야 한다.
- `0.0`은 편 상태, `1.0`은 최대 굽힘 상태로 정의한다.
- 손 크기와 카메라 거리에 따른 영향을 최소화해야 한다.
- 비정상적인 계산 결과는 허용 범위 안으로 제한해야 한다.

#### FR-03. 엄지 대립 및 벌림값 계산

**우선순위: Must**

시스템은 엄지 끝과 검지, 중지 및 손바닥 landmark의 상대 관계를 이용하여 엄지 대립 및 벌림 정도를 계산해야 한다.

인수 조건:

- 엄지 대립 및 벌림값을 `0.0~1.0`으로 표현해야 한다.
- 엄지가 검지 방향으로 접근하는 움직임을 구분할 수 있어야 한다.
- 손의 크기를 기준으로 거리를 정규화해야 한다.

#### FR-04. 사용자 캘리브레이션

**우선순위: Should**

시스템은 사용자마다 다른 손가락 가동범위를 보정할 수 있어야 한다.

인수 조건:

- 사용자의 편 손 자세를 최소값으로 저장할 수 있어야 한다.
- 사용자의 주먹 자세를 최대값으로 저장할 수 있어야 한다.
- 저장된 값은 손가락별 정규화에 적용되어야 한다.
- 비고
    
    사용자별 손의 값을 웹사이트 상에서 인식한 뒤 분석하고 시작함

### 3.2 명령 생성 및 전달

#### FR-05. 명령값 필터링

**우선순위: Must**

시스템은 손떨림과 landmark 오차가 모터의 급격한 움직임으로 전달되지 않도록 목표값을 필터링해야 한다.

인수 조건:

- 작은 변화는 deadband를 통해 무시할 수 있어야 한다.
- 이동평균 또는 저역통과필터를 적용해야 한다.
- 한 프레임에서 목표값이 급격하게 변경되지 않도록 제한해야 한다.

#### FR-06. ROS 2 손 명령 발행

**우선순위: Must**

Jetson은 계산된 7논리축 목표값을 ROS 2 토픽으로 발행해야 한다.

권장 토픽:

```
/thing/command/mimic → command_manager → /thing/command
```

명령 데이터에는 다음 정보가 포함되어야 한다.

- 메시지 생성 시간
- 메시지 순서 번호
- 손가락별 목표값 7개
- 제어 활성화 여부
- 제어 모드
- 최대 속도 또는 속도 제한값

인수 조건:

- 명령을 초당 20회 이상 발행해야 한다.
- 오래된 명령과 최신 명령을 구분할 수 있어야 한다.
- 목표값은 사전에 정의된 범위를 벗어나지 않아야 한다.
- 제어 모드는 `ControlState.msg`로 분리함

### 3.3 모터 제어

#### FR-07. 7채널 서보 제어

**우선순위: Must**

Raspberry Pi는 7개의 서보에 개별 목표 위치를 전달해야 한다.

인수 조건:

- 각 모터는 서로 다른 ID를 사용해야 한다.
- 손가락마다 최소 및 최대 모터 위치를 설정할 수 있어야 한다.
- 7개 모터에 서로 다른 목표값을 전달할 수 있어야 한다.
- 잘못된 목표값은 모터에 전달되기 전에 제한되어야 한다.

#### FR-08. 명령 보간 및 속도 제한

**우선순위: Must**

Raspberry Pi는 Jetson에서 전달된 목표값을 모터 제어 주기에 맞춰 부드럽게 보간해야 한다.

인수 조건:

- 목표 위치가 갑자기 변경되어도 모터가 즉시 최대 속도로 이동하지 않아야 한다.
- 손가락별 최대 속도를 설정할 수 있어야 한다.
- 엄지 대립 및 벌림축은 일반 손가락과 별도의 속도 제한값을 사용할 수 있어야 한다.

#### FR-09. 모터 상태 수집

**우선순위: Should**

시스템은 서보에서 제공하는 상태값을 수집해야 한다.

수집 대상:

- 실제 위치
- 목표 위치
- 속도
- 전류 또는 부하 추정값
- 온도
- 통신 상태

권장 토픽:

```
/joint_states, /thing/motor_status, /thing/diagnostics
```

#### FR-10. 초기 자세 설정

**우선순위: Must**

시스템 시작 시 로봇 손이 안전하게 정의된 초기 자세로 이동해야 한다.

인수 조건:

- 시스템 시작 직후 급격한 모터 움직임이 발생하지 않아야 한다.
- 초기 자세는 편 손 또는 중립 자세로 설정할 수 있어야 한다.
- 초기 자세 이동 시 낮은 속도 제한을 적용해야 한다.

### 3.4 안전 기능

#### FR-11. 통신 timeout 감지

**우선순위: Should**

Raspberry Pi는 마지막 정상 명령을 수신한 이후 경과 시간을 지속적으로 확인해야 한다.

인수 조건:

- 200~500ms 범위에서 timeout 기준값을 설정할 수 있어야 한다.
- timeout이 발생하면 새로운 일반 명령 실행을 중단해야 한다.
- timeout 발생 여부를 시스템 상태로 발행해야 한다.

#### FR-12. 안전 상태 전환

**우선순위: Should**

통신 단절 또는 시스템 오류 발생 시 시스템은 사전에 정의된 안전 상태로 전환해야 한다.

상태는 다음과 같이 구분한다.

```
INIT
→ READY
→ RUN
→ HOLD
→ SAFE 또는 FAULT
```

- `INIT`: 시스템과 모터 초기화
- `READY`: 제어 명령 대기
- `RUN`: 정상 손동작 추종
- `HOLD`: 짧은 통신 단절 시 현재 자세 유지
- `SAFE`: 장시간 통신 단절 시 안전 자세 수행
- `FAULT`: 과전류, 과온 또는 모터 통신 오류 상태

#### FR-13. 물리적 비상정지

**우선순위: Must**

ROS 2 및 소프트웨어 상태와 관계없이 모터 전원을 차단할 수 있는 물리적 비상정지 기능을 제공해야 한다.

인수 조건:

- 비상정지 작동 시 모터 구동 전원이 차단되어야 한다.
- Jetson 또는 Raspberry Pi가 멈춘 상태에서도 작동해야 한다.
- 비상정지 해제 후 자동으로 모터가 재동작하지 않아야 한다.

#### FR-14. 과전류 및 과온 보호

**우선순위: Should**

모터가 설정된 전류 또는 온도 기준값을 초과하면 시스템은 해당 모터의 동작을 제한하거나 중단해야 한다.

### 3.5 파지 기능

#### FR-15. 편 손과 주먹 동작

**우선순위: Must**

로봇 손은 사용자의 손동작 또는 사전 정의된 명령을 통해 편 손과 주먹 자세를 수행해야 한다.

인수 조건:

- 모든 손가락이 시각적으로 구분 가능한 편 손 자세를 만든다.
- 모든 손가락이 주먹 방향으로 굽혀진다.
- 편 손에서 주먹, 주먹에서 편 손으로 반복 전환할 수 있다.

#### FR-16. 원통형 물체 파지

**우선순위: Must**

로봇 손은 손바닥과 여러 손가락을 이용해 가벼운 원통형 물체를 파지해야 한다.

인수 조건:

- 지정된 위치에 놓인 원통형 물체를 감쌀 수 있어야 한다.
- 물체를 최소 3초 이상 유지해야 한다.
- 동일 물체를 10회 시험하여 7회 이상 성공해야 한다.

#### FR-17. 집기

**우선순위: Must**

- 로봇 손은 엄지 굽힘 및 대립축과 검지를 이용해 가벼운 소형 물체를 집어야 한다.
    
    인수 조건:
    
    - 엄지 끝과 검지 끝 또는 검지 측면이 접촉해야 한다.
    - 물체를 최소 3초 이상 유지해야 한다.
    - 지정된 물체를 10회 시험하여 7회 이상 성공해야 한다.

### 3.7 웹 기능

#### FR-19. 웹 모드 선택

**우선순위: Must**

시스템은 사용자가 웹사이트에서 로봇 손의 제어 방식을 선택할 수 있도록 해야 한다.

제공 모드:

- MIMIC: 실제 손동작 모방 모드
- MANUAL: 웹 버튼 기반 조작 모드

인수 조건:

- 사용자가 현재 선택된 제어 모드를 확인할 수 있어야 한다.
- 모방 모드와 조작 모드가 동시에 활성화되지 않아야 한다.
- 현재 제어 모드가 ROS 2 명령 메시지에 포함되어야 한다.
- 로봇 손이 동작 중이면서 안전한 상태(초기 자세)가 아닐 때에는 모드 변경이 불가능해야 한다.
→ 정지 버튼을 눌러서 안전한 상태(초기 자세)가 되어야만 모드를 변경할 수 있다.
- 두 모드 모두 웹에서 영상, landmark, 7논리축 목표값, 모터 상태 및 안전 상태를 확인할 수 있어야 한다.
- 녹화 중에는 MIMIC 모드에서 MANUAL 모드로 변경할 수 없어야 한다.
- 녹화 중인 상태에서는 모든 일반 모드 변경 요청을 거부해야 한다.

#### FR-20. 모방 모드 영상 표시

**우선순위: Must**

웹사이트는 모방 모드에서 사용자의 손을 촬영하는 카메라 영상을 실시간으로 표시해야 한다.

인수 조건:

- RGB 카메라 영상을 웹 화면에서 확인할 수 있어야 한다.
- 영상 위에 MediaPipe 손 landmark를 표시해야 한다.
- 손 검출 성공 여부를 표시해야 한다.
- 손이 검출되지 않으면 사용자에게 안내 메시지를 출력해야 한다.
- 카메라 연결이 끊어진 상태를 구분할 수 있어야 한다.
- 카메라와 Vision Node는 시스템 실행 중 항상 동작해야 한다.
- MJPEG 영상 스트리밍은 데이터 녹화 여부와 독립적으로 동작해야 한다.
- MJPEG 영상은 웹 관제 목적으로만 사용하며 파일로 저장하지 않아야 한다.

#### FR-21. 모방 모드 손동작 정보 표시

**우선순위: Must**

웹사이트는 MediaPipe를 통해 계산된 손동작 정보를 실시간으로 표시해야 한다.

표시 대상:

- 5개 손가락 굽힘값
- 엄지 대립 및 벌림값
- 총 7논리축 목표값
- 손 검출 신뢰도
- 현재 명령 발행 상태

인수 조건:

- 각 채널의 값을 `0.0~1.0` 범위로 표시해야 한다.
- 값의 변화를 숫자 또는 게이지 형태로 확인할 수 있어야 한다.
- 비정상적인 값은 화면에 표시하지 않고 오류 상태를 안내해야 한다.
- 기본 화면에는 직관적 데이터만 출력, 세부 데이터는 노출하지 않는다.
- 현재 통신 상태를 확인할 수 있어야 한다.

#### FR-22. 조작 모드 명령 입력

**우선순위: Must**

웹사이트는 조작 모드에서 버튼 입력을 통해 로봇 손에 명령을 전달할 수 있어야 한다.

기본 명령:

- 손 펴기
- 주먹 쥐기
- 원통형 물체 파지 자세
- 집기 자세
- 동작 정지
- 초기 자세 이동

추가 명령:

- 가위바위보
- 카운트다운

인수 조건:

- 사용자가 버튼을 통해 각 동작을 실행할 수 있어야 한다.
- 사용자 입력을 사전에 정의된 7논리축 목표값으로 변환해야 한다.
- 현재 명령이 실행 중인 경우, 다음 명령은 실행하지 않는다(queueing).
- 모방 모드에서는 조작 모드 명령이 실행되지 않아야 한다.
- 각 버튼은 직관적인 아이콘을 사용한다.

---

#### FR-23. 웹 명령 범위 제한

**우선순위: Must**

웹사이트에서 생성하는 명령은 사전에 정의된 안전 범위를 벗어나지 않아야 한다.

인수 조건:

- 7논리축 목표값은 각각 허용된 범위 안에서 생성되어야 한다.
- `NaN`, 무한대, 문자열 등 잘못된 값은 전달하지 않아야 한다.
- 한 번의 입력으로 목표값이 급격하게 변경되지 않아야 한다.
- 동작 정지 명령은 다른 일반 명령보다 우선하여 처리되어야 한다.
- 웹사이트는 모터에 직접 명령하지 않고 ROS 2 명령 인터페이스를 통해 전달해야 한다.

#### FR-24. 로봇 및 시스템 상태 모니터링

**우선순위: Must**

웹사이트는 로봇 손과 제어 시스템의 현재 상태를 표시해야 한다.

표시 대상:

- Jetson 연결 상태
- Raspberry Pi 연결 상태
- ROS 2 통신 상태
- 카메라 연결 상태
- 모터 연결 상태
- 현재 제어 모드
- watchdog 상태
- 안전 상태

인수 조건:

- 정상, 대기, 연결 끊김 및 오류 상태를 시각적으로 구분해야 한다.
- 모터 통신 오류가 발생한 경우 해당 모터를 식별할 수 있어야 한다.
- 통신이 끊기면 사용자에게 즉시 상태를 안내해야 한다.
- 상태 정보는 주기적으로 갱신되어야 한다.

#### FR-25. 모터 상태 표시

**우선순위: Should**

웹사이트는 Raspberry Pi가 발행한 모터 상태를 확인할 수 있도록 해야 한다.

표시 대상:

- 모터별 목표 위치
- 모터별 실제 위치
- 모터별 속도
- 모터별 전류
- 모터별 온도
- 모터 통신 상태

인수 조건:

- 7개 모터의 상태를 구분하여 표시해야 한다.
- 전류 또는 온도가 기준값을 초과하면 경고를 표시해야 한다.
- 상태값을 수신하지 못한 경우 마지막 값과 연결 끊김 상태를 구분해야 한다.
- 웹 화면의 상태 표시가 실제 모터 안전 제어를 대신해서는 안 된다.

#### FR-26. 데이터 기록 제어

**우선순위: Must**

웹사이트는 MIMIC 모드에서 실험 데이터 기록을 시작하고 종료할 수 있어야 한다.

인수 조건:

- 녹화 버튼은 MIMIC 모드에서만 활성화되어야 한다.
- 녹화 시작 요청 시 Logger가 Session ID를 생성해야 한다.
- 현재 녹화 상태와 Session ID를 웹에서 확인할 수 있어야 한다.
- 녹화 중에는 모드 변경 요청을 거부해야 한다.
- 웹에서 녹화 종료를 요청할 수 있어야 한다.
- 녹화 종료 후 사용자가 성공 또는 실패를 판정할 수 있어야 한다.
- 판정이 완료되기 전에는 다음 녹화를 시작할 수 없어야 한다.
- 카메라 영상은 저장하지 않아야 한다.
- rosbag2에는 MediaPipe landmark가 반드시 저장되어야 한다.
- WebSocket 메시지는 JSON 형식을 사용하며 세부 필드는 추후 확정한다.

---

#### FR-27. 웹 오류 및 안전 안내

**우선순위: Must**

웹사이트는 시스템 오류와 안전 상태를 사용자가 이해할 수 있도록 안내해야 한다.

안내 대상:

- 손 검출 실패
- 카메라 연결 실패
- ROS 2 통신 단절
- Raspberry Pi 연결 실패
- 모터 통신 오류
- timeout 발생
- 과전류 및 과온
- 비상정지 작동

인수 조건:

- 오류 발생 위치와 원인을 화면에 표시해야 한다.
- 위험 상태에서는 새로운 일반 조작 명령을 비활성화해야 한다.
- 비상정지가 작동한 경우 해제 전까지 조작 기능을 사용할 수 없어야 한다.
- 통신이 복구되더라도 사용자의 명시적인 제어 재개 입력 없이 자동으로 로봇 손을 움직이지 않아야 한다.

---

#### FR-28. 웹 실행 환경 제한

**우선순위: Must**

웹사이트는 프로젝트 전용 내부 네트워크에서 사용하는 것을 기본으로 해야 한다.

인수 조건:

- 외부 인터넷에서 직접 로봇 손을 제어할 수 없어야 한다.
- 웹 명령은 지정된 ROS 2 시스템에만 전달되어야 한다.
- 웹 서버가 중단되어도 Raspberry Pi의 모터 제한과 안전 기능은 독립적으로 동작해야 한다.

### 3.8 ROS 2 시스템 및 인터페이스

#### FR-29. ROS 2 패키지 모듈화

**우선순위: Must**

시스템은 기능별 책임을 분리한 ROS 2 패키지로 구성해야 한다.

권장 패키지:

| 패키지 | 주요 역할 | 실행 장치 |
| --- | --- | --- |
| `thing_interfaces` | 메시지·서비스·액션 정의 | 공통 |
| `thing_description` | URDF·mesh·RViz 설정 | 공통 |
| `thing_vision` | 카메라·MediaPipe·7축 목표·영상 overlay | Jetson |
| `thing_control` | 명령 중재·검증·안전·Gesture·Sequence | Raspberry Pi |
| `thing_hardware` | DYNAMIXEL 통신과 상태 수집 | Raspberry Pi |
| `thing_teleop` | 키보드 기반 개별축 제어 | Laptop 또는 Jetson |
| `thing_logger` | rosbag2와 SQLite 세션 관리 | Jetson 또는 Laptop |
| `thing_web_bridge` | WebSocket JSON과 ROS 2 연결 | Jetson |
| `thing_bringup` | Launch와 YAML 설정 | 공통 |

인수 조건:

- 각 패키지는 하나의 명확한 책임을 가져야 한다.
- `command_manager`와 `command_guard`는 독립 노드로 실행해야 한다.
- 공통 인터페이스는 `thing_interfaces`에서 관리해야 한다.
- 모든 패키지는 동일한 workspace에서 빌드할 수 있어야 한다.

#### FR-30. 사용자 정의 ROS 2 메시지

**우선순위: Must**

필수 메시지:

```
HandCommand.msg
HandLandmarks.msg
MotorState.msg
MotorStatus.msg
ControlState.msg
SafetyState.msg
RecordingState.msg
```

#### `HandCommand.msg`

```
uint8 SOURCE_UNKNOWN=0
uint8 SOURCE_MIMIC=1
uint8 SOURCE_TELEOP=2
uint8 SOURCE_GESTURE=3
uint8 SOURCE_SEQUENCE=4
uint8 SOURCE_SAFETY=5

builtin_interfaces/Time stamp
uint32 sequence
uint8 source

float32 thumb_flex
float32 thumb_opp
float32 thumb_abd
float32 index_flex
float32 middle_flex
float32 ring_flex
float32 little_flex

float32 speed_limit
float32 confidence
```

- 7개 논리축은 배열이 아닌 고정 필드로 정의한다.
- `thumb_opp`는 엄지 가로 방향 대립축, `thumb_abd`는 엄지 세로 방향 벌림축으로 정의한다.
- 각 논리축 값은 `0.0~1.0` 범위를 사용한다.
- `0.0`은 펼침, `1.0`은 최대 굽힘 또는 대립으로 정의한다.

#### `ControlState.msg`

```
uint8 MODE_DISABLED=0
uint8 MODE_MIMIC=1
uint8 MODE_MANUAL=2
uint8 MODE_TELEOP=3

uint8 OWNER_NONE=0
uint8 OWNER_WEB=1
uint8 OWNER_LOCAL=2

builtin_interfaces/Time stamp
uint8 active_mode
uint8 active_owner
bool owner_alive
bool sequence_running
string last_transition_reason
```

#### `SafetyState.msg`

uint8 INIT=0

uint8 HOLD=3
uint8 SAFE=4

#### `HandLandmarks.msg`

```
uint8 HANDEDNESS_UNKNOWN=0
uint8 HANDEDNESS_LEFT=1
uint8 HANDEDNESS_RIGHT=2

std_msgs/Header header
bool detected
float32 confidence
uint8 handedness
float32 handedness_confidence
uint32 image_width
uint32 image_height
geometry_msgs/Point32[21] landmarks
```

인수 조건:

- `header.stamp`는 가능한 한 카메라 프레임 획득 시각을 사용해야 한다.
- `header.frame_id`는 카메라 optical frame을 사용해야 한다.
- landmark의 `x`, `y`는 영상 너비와 높이에 대해 정규화된 좌표여야 한다.
- landmark의 `z`는 MediaPipe가 제공하는 손목 기준 상대 깊이이며 실제 미터 단위 깊이로 해석하지 않아야 한다.
- `detected=false`일 때 landmark 배열을 유효한 손 좌표로 사용하지 않아야 하며 `confidence=0.0`으로 발행해야 한다.
- landmark 배열은 MediaPipe Hands의 0번부터 20번까지 고정된 순서를 사용해야 한다.

#### `MotorState.msg`

```
uint8 motor_id
string actuator_name
int32 goal_position_raw
int32 present_position_raw
float64 goal_position_rad
float64 present_position_rad
float64 velocity_rad_s
float64 current_ampere
float64 voltage_volt
float32 temperature_celsius
uint32 hardware_error
int32 communication_result
bool communication_ok
```

인수 조건:

- 모터의 raw encoder 값과 SI 단위 변환값을 함께 제공해야 한다.
- `actuator_name`, motor ID와 7개 논리축의 연결 관계는 YAML에서 관리해야 한다.
- 해당 주기에 값을 읽지 못하면 `communication_ok=false`로 발행해야 한다.
- 읽을 수 없는 실수 필드는 `NaN`으로 표시하고 정상 측정값처럼 사용하지 않아야 한다.
- 위치는 rad, 속도는 rad/s, 전류는 A, 전압은 V, 온도는 섭씨 단위를 사용해야 한다.

#### `MotorStatus.msg`

```
std_msgs/Header header
MotorState[] motors
bool bus_communication_ok
uint32 failed_read_count
string message
```

인수 조건:

- `header.stamp`는 Raspberry Pi가 해당 상태 묶음을 읽은 시각이어야 한다.
- `motors`는 설정된 motor ID 오름차순으로 발행해야 한다.
- 일부 모터 읽기에 실패해도 성공한 모터의 상태는 함께 발행해야 한다.
- `bus_communication_ok`는 설정된 전체 모터와 정상 통신했을 때만 `true`여야 한다.
- `failed_read_count`는 모터 노드 시작 이후의 누적 읽기 실패 횟수여야 한다.
- 물리 모터 수가 변경되어도 `MotorStatus.msg` 정의 자체를 수정하지 않아야 한다.

#### `RecordingState.msg`

```
uint8 IDLE=0
uint8 STARTING=1
uint8 RECORDING=2
uint8 STOPPING=3
uint8 COMPLETED=4
uint8 FAILED=5
uint8 INTERRUPTED=6

uint8 RESULT_UNSET=0
uint8 RESULT_SUCCESS=1
uint8 RESULT_FAILURE=2

std_msgs/Header header
uint8 state

uint64 active_session_id
string active_bag_path
builtin_interfaces/Time active_started_at

uint64 last_session_id
string last_bag_path
builtin_interfaces/Time last_started_at
builtin_interfaces/Time last_ended_at

bool result_pending
uint8 last_mimic_result
string message
```

인수 조건:

- `active_session_id`는 현재 녹화 중인 Session ID이며 활성 세션이 없으면 `0`이어야 한다.
- `last_session_id`는 가장 최근에 종료된 Session ID여야 한다.
- `result_pending`은 마지막 종료 세션의 미믹 성공·실패 판정이 아직 입력되지 않았음을 나타내야 한다.
- `last_mimic_result`는 판정 전 `RESULT_UNSET`, 성공 `RESULT_SUCCESS`, 실패 `RESULT_FAILURE`를 사용해야 한다.
- `STARTING`과 `STOPPING` 상태에서는 웹의 중복 시작·종료 요청을 비활성화할 수 있어야 한다.
- 녹화 시작 서비스가 반환한 Session ID와 `active_session_id`는 일치해야 한다.
- 녹화 종료 후 `active_session_id=0`, `last_session_id=종료된 Session ID`로 발행해야 한다.
