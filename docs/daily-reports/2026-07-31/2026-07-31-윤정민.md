## 오늘 한 일

- **Safety Manager를 8상태로 구현함.**
  - 기존 `INIT·READY·RUN·HOLD·SAFE·FAULT·ESTOP`에 정상 제어권 종료·교대를 위한 `RESET`을 추가함.
  - `RUN → HOLD` 300ms, `HOLD → SAFE` 총 1000ms, 연속 유효 activity 300ms 후 `HOLD → RUN` 복구 정책을 구현함.
  - SAFE·FAULT는 원인 해소 1000ms, ESTOP은 fresh inactive heartbeat 500ms 이후 `/thing/reset_safety`로 INIT 재검사를 수행하도록 구성함.
  - 정상 RESET은 최소 500ms 동안 유지하고, RESET 진입 후 측정된 7개 모터의 torque OFF를 확인해 READY로 전환하며 3000ms에 도달하면 FAULT를 우선하도록 처리함.
- **Command Manager·Command Guard와 Safety Manager의 정지 경로를 연결함.**
  - `SetControlMode(DISABLED, NONE)` 요청 후 Command Guard가 STOP latch를 닫고 내부 causal ACK을 발행한 뒤 Safety Manager가 RESET에 진입하도록 순서를 고정함.
  - HOLD·RESET·SAFE·FAULT·ESTOP에서 일반 명령을 차단하고, HOLD의 간헐 activity가 원래 SAFE deadline을 연장하지 않도록 처리함.
  - E-Stop과 MotorStatus heartbeat의 300ms 초과 gap을 callback 단계에서 감지하여 timer 지연 중 재개된 입력이 stale 구간을 숨기지 못하도록 보강함.
- **안전 입력과 시간 경계를 fail-closed 방식으로 검증함.**
  - watchdog·RESET·heartbeat 경과시간은 steady clock, ROS stamp와 source 시각 비교는 system clock으로 분리함.
  - MotorStatus의 7개 고유 ID, 통신 상태, 모든 실수 telemetry의 유한값, source freshness·future·replay와 canonical timestamp를 검사함.
  - startup에서 E-Stop 또는 MotorStatus가 들어오지 않으면 300ms 뒤 각각 ESTOP·FAULT로 전환하고, 동시에 발생하면 ESTOP 우선순위를 유지함.
  - 실물 시험으로 확정되지 않은 전류·온도 trip 값은 `trip_limits_validated: false`에서 INIT을 유지하도록 구성함.
- **ROS 2 실행·보안 경로와 문서를 정리함.**
  - `SafetyState.RESET=7`과 `MotorState.torque_enabled`만 공개 인터페이스에 추가하고 custom reset service와 generation 필드는 추가하지 않음.
  - SROS2 policy를 구성하고 production launch가 보안 비활성 상태나 필수 enclave artifact 누락 시 node를 시작하지 않도록 처리함.
  - 상태 전이, timeout, heartbeat, RESET 완료 조건과 hardware·Web 책임 경계를 `docs/interfaces.md`, `docs/safety_manager.md`에 기록함.
