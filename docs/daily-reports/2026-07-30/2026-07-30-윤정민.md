- **Command Manager가 선택한 명령을 최종 검증하는 Command Guard를 구현함.**
  - `/thing/command/selected`, `/thing/safety_state`, `/thing/control_state`를 입력으로 받고 모든 검사를 통과한 `HandCommand`만 `/thing/command`로 전달하도록 구성함.
  - MIMIC·MANUAL·TELEOP의 mode·owner·source 조합을 검사하고, 현재 제어권과 맞지 않는 입력을 fail-closed 방식으로 거부함.
  - SafetyState·ControlState가 없거나 오래된 경우와 INIT·HOLD·SAFE·FAULT·ESTOP 상태에서 일반 명령을 차단함.
- **HandCommand 전체 필드의 유효성 검사를 구현함.**
  - system time 기준으로 300ms를 초과한 stale 명령과 100ms를 초과해 미래로 설정된 명령을 거부함.
  - source별 uint32 sequence의 중복·역행을 차단하고 `0xffffffff → 0` 순환은 정상 순서로 처리함.
  - 7개 논리축의 누락·NaN·Inf·`0.0~1.0` 범위 초과를 검사하고, 축별 최대 변화율과 `speed_limit`을 이용해 급격한 목표 변경을 차단함.
  - `speed_limit`과 `confidence`의 유한값 및 허용 범위를 검사하고, 거부된 명령은 sequence와 이전 축 상태를 갱신하지 않도록 처리함.
- **HOLD 이후 자동 재개를 차단하는 복구 정책을 반영함.**
  - HOLD를 사용자 일시정지가 아니라 300ms 명령 단절 시 현재 보간 setpoint를 유지하는 watchdog 상태로 구분함.
  - HOLD 뒤 SafetyState가 READY로만 복구되어도 이전 mode·owner를 다시 신뢰하지 않고, `DISABLED·NONE → 새 mode·owner 획득` 전이를 관측한 뒤 새 명령을 허용하도록 수정함.
- **운영 실행과 진단 경로를 구성함.**
  - 거부 시 `/thing/diagnostics`에 즉시 WARN과 사유를 발행하고, 마지막 판단을 최대 1000ms 주기로 반복 발행하도록 구현함.
  - command timestamp·diagnostic timestamp·diagnostic timer는 SYSTEM_TIME, 상태 freshness와 축 변화 경과 시간은 monotonic clock을 사용함.
  - `control.yaml`에 timeout·7축 범위·변화율을 정의하고 안전 기준보다 느슨한 설정은 node 시작 단계에서 거부하도록 처리함.

## 막힌 점 또는 위험 요소

- Command Guard 내부 `RLock`은 같은 process의 callback 충돌만 막으며, 서로 다른 DDS topic의 STOP·FAULT와 일반 명령 사이 전역 수신 순서는 보장하지 않음.
